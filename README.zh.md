# Semantic Decompression：语义解压

让密集材料变得可理解，而不丢失原意。

Semantic Decompression 是一个纯指令 Skill，用来补回作者默认读者已经知道的背景和联系。它保留正式术语、原始主张与不确定性，同时解释谁在行动、状态怎样改变、结论为什么成立，以及证据到哪里为止。

## 适用场景

当摘要或术语表仍不足以让人理解材料时，可以使用这个 Skill：接手陌生架构、理解压缩的论证、解释指标口径，或把专家笔记转成伴读说明与接手教程。

展开深度由任务决定。一个局部区别可能只需要两句话；一篇完整教程可能需要整体关系、贯穿示例和边界说明。Skill 不强制使用固定的输出模板。

纯摘要、直译、润色、压缩包解压和代码修复不会自动触发。在混合请求中，Skill 只处理需要解释的部分，不接管其他任务。

## 示例

下面是教学片段，不代表真实司法辖区的规则。

**原文**

> 申请在实质性完整后进入法定审查期，补件会中止时钟。

**解释**

> 原文给出的计时起点是“实质性完整”，而不是单纯提交申请；要求补件会中止计时。但这句话没有说明谁来认定完整、具体期限是多少，也没有说明计时恢复的条件。尤其不能直接推断为“只要把补件交上去，时钟就恢复”。

补回理解所需的区别，同时不补造材料没有给出的规则。

## 安装

在宿主支持的 Skill 位置创建 `semantic-decompression` 目录，并放入运行文件：

```text
semantic-decompression/
  SKILL.md
  references/
    decompression-lenses.md
    multi-source-boundaries.md
```

保持相对路径不变。也可以复制整个仓库，但只有上述文件属于运行指令。更新前保留本地修改，避免同时启用多个同名副本。

Skill 的发现、调用、权限和模型选择由宿主控制，安装位置与调用方式以宿主文档为准。本项目不要求特定模型、可执行脚本、依赖包或 API Key。需要获取源材料时，使用宿主提供的工具。

## 使用

直接描述需要解释的内容，并给出必要的读者、来源或格式约束：

> 把这段架构给新同事讲清楚。保留正式术语，走通材料支持的流程；没有给出的崩溃恢复机制继续标为未知。

> 我已经懂基础，只用两句话解释“接收成功”和“提交完成”的区别。

> 先翻译，再解释这段话的前提。只返回我指定的 JSON 字段。

完整工作方法见 [`SKILL.md`](SKILL.md)：适配读者，锚定主张，定位缺失联系，选择解释路线，在需要处展开，最后对照来源核验。

两个 reference 均按需读取。[Decompression lenses](references/decompression-lenses.md) 用于诊断较难识别的理解缺口；[Multi-source boundaries](references/multi-source-boundaries.md) 用于处理真正影响结论状态、来源或覆盖范围的差异。材料位于仓库中，本身不会触发全仓审计。

## 边界

流畅的解释不能代替缺失的证据。可以解释一般概念、标明未知、给出有依据的推论或假设示例，但不能将其写成来源已经确立的事实。忠实于来源也不等于认可错误：有依据的纠正需要与原始主张分开呈现。

在宿主 system 和 developer 约束内，用户指定的读者、语言、结构、篇幅与来源范围决定解释方式。
